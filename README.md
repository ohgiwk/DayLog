# DayLog

Vue + TypeScript の日記アプリ。日記は端末内に自動保存し、ログイン時は Supabase Auth / Postgres / 非公開 Storage と同期します。

## 開発

```sh
npm ci
cp .env.example .env.local
# .env.local に Supabase の URL と publishable key を設定
npm run dev
npm test
npm run build
```

`service_role` / secret key はブラウザに設定しないでください。GitHub Pages のビルドには、ワークフローに DayLog の公開 URL と publishable key を指定しています。リポジトリ変数 `VITE_SUPABASE_URL` / `VITE_SUPABASE_PUBLISHABLE_KEY` で上書きできます。

設定画面の最下部には、そのアプリを配信したプッシュ日時を日本時間のバージョン表記（例：`v2026.10.26-120405`）で表示します。GitHub Actionsがpushイベントの日時をビルドに埋め込むため、起動日時や端末のタイムゾーンには影響されません。手動デプロイ・ローカルビルドではビルド日時を使います。`version.json` の `releasedAt` にも同じ日時を出力します。

## アカウントの使い方

1. 未ログインでアプリを開くとログイン画面へ移ります。「新規登録」で登録し、確認メールのリンクを開きます。
2. 各端末で同じメールアドレスとパスワードを使ってログインします。ログイン後は記録、または開こうとしていた日記の画面に移ります。
3. ログイン前の日記は「端末の日記を取り込む」で写真と一緒にアップロードできます。同じ日付が同期先にある場合は上書きせず、元の端末データに残します。

日記・回答・写真・削除を同期します。メモと表示設定は端末ごとです。変更は端末に保存してから送信します。画面復帰・再接続・30秒ごとの確認でも同期し、フォーム編集中は他端末の変更によるフォームの差し替えを避けます。同じ日付の編集が競合した場合は設定で両方の内容を比較して選択します。未同期の変更がある間はログアウトを止め、データを保持します。

端末内キャッシュはアカウント別です。ログアウトしても未ログイン時の日記は残ります。共有端末ではブラウザのサイトデータにキャッシュが残ることに注意してください。

## Supabase

既存 DayLog プロジェクト: `twrpxwrznilnnxsfklir`。

- `supabase/migrations/`: 適用済みの DB・写真ポリシー。日記は `daylog_entries`、写真は非公開バケット `daylog-photos`。
- `supabase/config.toml`: 確認・再設定メールのリダイレクト先。既存のその他の設定は変更しません。
- 日記・写真は `auth.uid()` による本人限定の RLS を適用。
- 日記保存 RPC は invoker 権限で、バージョンが一致する場合だけ更新。削除の印を残してオフライン端末による意図しない復活を防ぎます。
- 写真削除は日記の同期成功後に実行し、失敗した削除も再試行します。
- メール確認は有効です。実ユーザー向けに展開する場合は Supabase の SMTP 設定・メール送信制限を確認してください。標準送信サービスは用途・送信先に制限があります。
- PKCE の確認・再設定リンクはリクエストしたブラウザで開いてください。PWAで登録した場合、メール確認後にPWAへ戻り、通常のログインを利用できます。

### 検証

`npm test` は Vitest で実行します。通常のロジック・同期通信は Node、HTML処理・更新通知は jsdom、保存トランザクションは fake-indexeddb で検証します。実アカウント・実DBには接続しません。

| 対象 | 主な検証内容 |
| --- | --- |
| 日記・メモの同期モデル | 送信中の追加編集、競合の検知・解決、独立した変更の統合、削除、失われた応答からの回復 |
| 同期通信 | オフライン・送信失敗後の再試行、編集中の取り込み抑止、アカウント切り替え後の応答、多重送信防止 |
| IndexedDB・メモ保存 | コミット後の通知、失敗時のロールバック、同時編集、アカウント分離、旧メモの一度だけの取り込み |
| 写真 | 端末キャッシュ、ダウンロード、アカウント切り替え中の取得、圧縮サイズ・失敗時のリソース解放 |
| HTML・設定 | 実行可能な要素・属性の除去、書式・写真の維持、壊れた設定からの起動 |
| 起動・認証・更新 | 起動順序、認証失敗時の保護、画面遷移、更新通知の再表示・確認、保存失敗時の更新中断 |

日本時間の深夜の日付判定も含めて確認する場合は `TZ=Asia/Tokyo npm test` を実行します。`npm run build` はテストコードを含む型チェックと本番ビルドを行います。

保存とHTML処理はそれぞれ `src/lib/indexed-db.ts` と `src/lib/html-sanitizer.ts` に共通化しています。日記・メモで許可する書式や画像は個別のポリシーとして維持します。

jsdom と fake-indexeddb は実ブラウザのレイアウトやOSの機能を再現しません。カメラ・位置情報の権限、iOSホーム画面からの再起動、実ネットワーク・複数端末での同期、編集画面全体の操作は別途実機で確認してください。

実サーバー検証は、**使い捨てのメール確認済みアカウント2件**だけで実行します。実ユーザーでは実行しないでください。

```sh
DAYLOG_TEST_ACCOUNTS=/private/tmp/disposable-accounts.json \
VITE_SUPABASE_URL=https://your-project.supabase.co \
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_... \
node scripts/verify-cloud.mjs
```

アカウントファイル形式は `[{"id":"...","email":"...","password":"..."}, ...]`。ファイルはGitに追加しないでください。スクリプトは独立した2端末相当のログイン、写真同期、別アカウントへの遮断、競合、削除を検証します。終了時にテスト写真を削除し、セッションを破棄します。テスト用アカウントと日記の削除印は実行者が後で削除してください。

## オフライン利用

本番版をオンラインで一度開き、ログインしておくと、起動用ファイルの保存完了後はオフラインでも再起動・画面移動・日記の記録ができます。本文は端末内、追加した写真はIndexedDBに保存され、再接続後に自動同期します。端末に保存していない写真の取得、初回ログイン、天気の取得には通信が必要です。

Service WorkerはHTTPS（またはlocalhost）の本番ビルドで有効になります。初回アクセスそのものがオフラインの場合や、ブラウザのサイトデータを削除した場合は、オンラインで開き直してください。開発サーバーでは登録しません。全画面のJS/CSSを先に保存するため、未訪問の画面もオフラインで開けます。認証APIや日記の通信レスポンスはService Workerにキャッシュしません。
